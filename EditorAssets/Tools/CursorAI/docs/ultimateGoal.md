# 最終目標（ユーザー正本）

「完成形の説明」だけを、ユーザーが `[大見出し]` / `〇中見出し` / `・小見出し` で書く。エージェントは見出しの構成を変えず、本文を埋めない・書き換えない。

タスク着手前の査定は `.cursor/rules/ultimate-goal.mdc` と `cursorInstructions.md` §6.7。査定の単位は「完成形の説明」にある `・` の行だけである。`[]` と `〇` はその行のまとまりを示す。「エンジンとしての前提」はギャップスキャンの後段であり、査定の基準にしない。このファイルは `engineRoadmap_rough.md` / `gameRoadmap_rough.md` ではなく、記号をロードマップのタスクとして取り込まない。

## このファイルの書き方

「完成形の説明」は、次の順で繰り返す。

```
[大見出し]
〇中見出し
・完成したあと、誰がどの流れを最後まで通せるかを1行で書く
```

- `・` の1行が本文であり、査定の単位。`[]` と `〇` だけでは目標にしない。
- チェックボックスと実装手順は書かない。実行単位は `feature-memos/engineRoadmap.md` と `feature-memos/gameRoadmap.md`。
- まだ書かない行は `（未記入）` にする。

## 完成形の説明
[アセット]</br>
〇自作エディタ上</br>
・ファイル内部の編集とは別の、ファイルの新規作成や削除、名前変更などが行えるようになっている</br>
〇自作エディタと外部ツールの棲み分け</br>
・jsonなどインスペクタで簡易的に内部の編集が可能なファイルには自作エディタのインスペクタを使用する</br>
・png含む画像や、objやgltf含む3Dモデルデータなど便利な既存の外部ツールがありインスペクタでの編集の優先度が低いファイル内部の編集には外部ツールを使用する</br>
・mdファイルやluaファイルなどコード類、テキスト類のファイル内部の編集にはVsCodeなど外部のテキストエディタを使用する</br>

[基本機能とコンポーネント]</br>
〇基本機能</br>
・シーンマネージャーやオーディオマネージャー、入力マネージャー、描画エンジンや物理エンジン(形状データを除く)などの1つしか存在しない仕組みや状態をもたない計算処理が基本機能として独立している</br>
・基本機能に外部クラスからアクセスできるようになっている</br>

[クラス分け]</br>
〇部品単位のクラス分け</br>
・機能として成り立つ最小単位の部品がそれぞれクラスに分けられ整理されている</br>
・機能が重複するクラスが無い</br>

[エディタ] </br>
〇エンティティ</br>
・各エンティティのコンポーネント構成やコンポーネント内部のパラメータをjsonデータとして作成/保存/編集/削除することができる</br>
・エンティティをプレハブ化してjsonデータとしてアセット保存することができる</br>
・ゲーム内のロジック(スクリプト)によって、保存したエンティティをゲーム内に生成することができる</br>
・シーンの構成を保存することと、ゲーム中にエディタ上でのプレイとゲーム配布のランタイム環境上でのプレイを可能にしてある</br>

[入力マッピング]</br>
〇入力の抽象化</br>
・エディタ上で入力マッピング(ボタンとキーのエイリアス)を設定する</br>
・入力マッピングをjson保存して、ゲーム配布時にはリソース配布のルールに従って指定フォルダに出力する</br>

[エディターのexe化]</br>
〇エディターのexe化</br>
・エディター用のアセットとexeを同梱配布する</br>
・エディタ用のアセットの中にゲーム再生用のテンプレートexeをもっている</br>
・ゲーム配布時にはテンプレートexeとアセットを指定出力先にコピー出力する</br>
・エディターをexe(Development配布)化する</br>

[ランタイム出力]</br>
〇ランタイム出力</br>
・エディターからjson等データを作成し、指定の出力先にランタイムテンプレートexeと同梱コピーすることでゲームとして動かせる</br>

[リソース作成]</br>
〇リソース作成</br>
・pngやobj、gltfなど画像や3Dモデル、アニメーションのリソースの作成は外部ツールで行う</br>

[リソース配布]</br>
〇リソース配布</br>
・ゲーム配布の際、pngやobj、jsonはddsやバイナリなどに圧縮して配布し、ゲーム中に読み込む</br>

[アニメーション]</br>
〇アニメーション</br>
・外部ツールBlenderで作成したgltfを読み込んでその通りにアニメーションさせられる</br>
・ゲーム中のロジックに従って実行/制御することができる(実行中に媒介変数tを操作するなど)</br>

[グラフィックス]</br>
〇グラフィクスエンティティ</br>
・ライトをコンポーネント化してあり、Lightエンティティを配置/編集/削除できる</br>
・VolumetricFogをコンポーネント化してあり、VolFogエンティティを配置/編集/削除できる</br>
・ライトやvolumetricFogのようなグラフィックスエンティティとして実装できるものは全てコンポーネント化して空きエンティティに付加することや、他エンティティに影響を及すことができるようにしてある</br>

[当たり判定]</br>
〇プリミティブ同士の当たり判定</br>
・プリミティブ(直方体や球、円柱やカプセル、面や線)同士の当たり判定が実装してある</br>
・異なるプリミティブ同士の当たり判定が実装してある</br>
〇isTrigger
・Trigger(当たり判定のみの状態)とCollision(後述の衝突応答ありの状態)がそれぞれ用意してある

[物理演算]</br>
〇プリミティブ同士の衝突</br>
・プリミティブ(直方体や球、円柱やカプセル、面)同士の衝突応答が当たり判定とは別に実装してある</br>
・異なるプリミティブ同士の衝突応答が実装してある</br>
〇情報取得</br>
・直前の演算で衝突したオブジェクト双方の情報を外部からも取得できるようになっている</br>

[オーディオ]</br>
〇読み込み</br>
・mp4やwavなど代表的な拡張子の音源ファイルを読み込める</br>
〇再生</br>
・bgmとしてのループ再生ができる</br>
・サイズが大きい音源ファイルについてストリーミング再生ができる</br>
〇コンポーネント</br>
・コンポーネント化してある</br>
・再生時の音量の割合をインスペクタで指定してコンポーネントのパラメータとして保存し、再生時に反映できる</br>
・コンポーネントで複数の音源ファイルを指定できる</br>
〇ファイルパスにエイリアス</br>
・音源ファイルのパスにエイリアスを付けて基本はエイリアスで管理し、エイリアスのテキストをクリックしたら実際の相対ファイルパスが見られるようになっている</br>
・音源ファイルのエイリアスを1つのjsonファイルなどにまとめ、リスト化して一元管理できている</br>
・音源ファイルのエイリアスとファイルパスの対応リスト、その項目をエディタ上で検索/閲覧/編集/削除することができる</br>
・ゲーム中でマスターボリュームや効果音、bgmなどまとめて音量割合をプレイヤーが設定し、その設定を保存/反映できるようになっている</br>

[スクリプト]</br>
〇編集</br>
・スクリプトをエディタから新規作成/保存/編集/削除できる</br>
・スクリプトの中身のコードの編集についてはVsCodeなど外部ツールを利用する
〇動作</br>
・スクリプトを読み込んで実際に中身のコードを動作させられる</br>
〇C++との連携</br>
・C++側のバインドができていて、C++側の汎用コードを活用できるようになっている</br>

[カメラ]</br>
〇デモ的なカメラワーク</br>
・ムービーシーンなどでシネマチックな演出を行うことができる
〇ゲーム中のカメラワーク
・マリオオデッセイのように、プレイヤーがカメラを直接操作せずとも自動でカメラが動作し、見やすいカメラワークをとるようになっている
・自動カメラワークを取り入れつつ、プレイヤーの操作もある程度反映するかどうか、どの程度反映するかを設定/保存し、アセット化できるようになっている

[デバッグ]</br>
〇エディタ上テストプレイ時の情報の確認</br>
・ストリーミングのメモリ消費量や進行度を開発用Guiで確認できる</br>
・存在するエンティティ全体のメモリ消費量を開発用Guiで確認できる</br>
・エンティティ全体のメモリ消費量の確認を行うGuiの中にエンティティの名前を入れる検索スペースがあり、入力があり、かつ一致する名前のエンティティがある場合に該当エンティティの個別のメモリ消費量を確認できるようになっている</br>
・メモリ消費量を確認する際にリアルタイムでグラフを出し、直近1秒、のメモリ消費量の遷移を目視で確認できるようになっている</br>

[UI/HUD]</br>
〇オペレーター機能</br>
・プレイヤーが特定の操作を一定以上の時間行っていない、自機が特定の座標範囲に入った、特定のエンティティとプレイヤーが近づいている等々の特定条件下においてテキストや画像などスプライトを用いてヒントやナビの表示(操作キーやボタン含むアクションの提示や、対処法の示唆など)を行えるようになっている</br>
・フォントや文字色、背景色、吹き出しの形状などを設定し、アセットとして扱えるようになっている</br>
〇HUD</br>
・特定のコンポーネントから値を取得して、画像を使用した個数アイコンや個数ゲージ、簡易的な割合バー、あるいは数字用の画像を使用した数字としてスプライト描画することができる</br>

[シーン遷移]</br>
〇シーン遷移のロジック</br>
・シーン遷移の条件(処理の呼び出し)をスクリプトに記述して実行することができる</br>

[]</br>

## エンジンとしての前提

ギャップスキャンが、完成形の説明を一巡したあとだけ見る補足である。§6.7 の査定基準にはしない。完成形に無い系統は書かない。

[時間]
〇フレーム時間
・フレーム時間と一時停止を、物理・アニメーション・シーン遷移が同じ基準で使う

[階層]
〇トランスフォーム
・エンティティの親子関係と、ローカル座標からワールド座標への変換ができる

[リソース]
〇解放
・シーンを離れたときに、そのシーンが使っていたリソースを解放できる

[見た目]
〇マテリアル
・モデルとテクスチャをエンティティの見た目に結び付けるマテリアルを持てる

[移動]
〇レイヤーとプレイヤー移動
・プリミティブ衝突に加え、衝突レイヤーと、プレイヤーが地形の上を動く移動ができる

[ウィンドウ]
〇表示設定
・配布した exe で解像度・全画面・垂直同期を設定できる

[失敗の見え方]
〇アセットとスクリプト
・読めないアセットやスクリプトの失敗が、黙って消えず分かる

[データ形式]
〇版
・エンティティや入力マップなどの json は、形式の版が変わったとき旧データを読めるか、拒否理由が分かっている
