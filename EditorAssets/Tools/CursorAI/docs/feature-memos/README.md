# 実装したい機能メモ（ロードマップ運用）

配置: **`EditorAssets/Tools/CursorAI/docs/feature-memos/`**（Cursor 半自律用。リポジトリ直下の `docs/` は使わない）。

正本は **`roadmap.md` のみ**。箇条書きとチェックで進捗を管理する。

| ファイル | 用途 |
|----------|------|
| **`roadmap_rough.md`** | 下書き（常にテンプレ＋貼付欄） |
| **`roadmap_rough.template.md`** | 再生成用テンプレ（編集はこちら） |
| **`roadmap_rough_old.md`** | 直近1回分の取り込み退避（本文は `roadmap.md` へ取り込み済み・重複なし） |
| **`entity_camera_components.md`** | エンティティカメラの要件・段階ロードマップ（チェック付き正本） |
| **`roadmap.md`** | 正本（`##` / `###` / `- [ ]`・`- [x]`） |

## 書き方

**下書き** … `[大見出し]` / `〇中見出し` / `・小見出し`（本文行なし。大見出しは `<>` ではなく `[]`）

**正本 `roadmap.md`**

- `##` 大見出し、`###` 中見出し、`- [ ]` 小見出し（実装・チェック単位）
- 1行に足りないときは **その行の下にメモをインデント**するか、同じフォルダに `boss-intro-camera.md` を追加し、行末に `（spec: boss-intro-camera.md）` と書く（任意）

## 下書きから取り込む

1. `roadmap_rough.md` に `[]` / `〇` / `・` で貼る
2. 半自律開始時、エージェントが **下書きを解釈** → `roadmap.md` に起こす（§6.1：追加・細分化・統合）
3. 取り込み後: 先頭に `取り込み済み yyyy-mm-dd(ddd)_HH-MM-SS` を付けたうえで **`roadmap_rough_old.md` に改名** → `roadmap_rough.template.md` から **新 `roadmap_rough.md` を生成**

既存の `roadmap.md` と **マージ**する（完了 `[x]` は消さない）。次の下書きは新しい `roadmap_rough.md` の「（以下に貼る）」へ貼る。

## 半自律での流れ

1. `roadmap_rough.md` の貼付欄に `[]`/`〇`/`・` があれば **先に起こし**（退避・テンプレ再生成）→ 続いて `roadmap.md` を Read
2. **解釈**し、必要なら roadmap を **追加・細分化・統合**（理由を `progress_report.md` に）
3. 曖昧 → **ユーザーへ質問**（回答待ち）。まだ曖昧 → **要件の再定義を要請**（実装しない）
4. 実装済みと判断した小見出しは **`[x]`**（作業スキップ）→ **`progress_report.md`** の「実装済みと判断した項目」に根拠を記載（実装が無いセッションでも必須）
5. 悪影響・依存で見送る項目は **`- [-]`**（他の `- [ ]` のみ実装。理由は `progress_report` §保留）
6. 明確になったら **`- [ ]` 1件** だけ実装 → `buildDevelopment.cmd` → `[x]`

手入れ案だけ確認: **「roadmap の手入れまで承認して」**

`EditorAssets/Tools/CursorAI/task_backlog.md` は「次に roadmap のどこから」などの **優先指示用**（空なら roadmap の上から）。

## チェック記号

| 記号 | 意味 |
|------|------|
| `- [ ]` | 未着手 |
| `- [~]` | 進行中（任意） |
| `- [x]` | 完了 |
